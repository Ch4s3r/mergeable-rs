# Releases and versioning

mergeable-rs is released automatically from `main`.

## Versions from conventional commits

Every push to `main` runs `.github/workflows/release.yml`:

1. `devenv test` (format, clippy, unit and contract tests).
2. [git-cliff](https://git-cliff.org) (`git cliff --bumped-version`, configured in `cliff.toml`) computes the next
   [semantic version](https://semver.org) from the [conventional commits](https://www.conventionalcommits.org) since
   the last `v*` tag. While below 1.0.0, `feat` and breaking changes bump the minor version and `fix`, `perf` and the
   other types bump the patch version. The first release was 0.1.0. Without
   releasable commits nothing is published.
3. The image is built with Paketo buildpacks and published as `ghcr.io/ch4s3r/mergeable-rs:<version>` and
   `ghcr.io/ch4s3r/mergeable-rs:latest`, with the OCI labels for source, version and revision.
4. [crane](https://github.com/google/go-containerregistry/tree/main/cmd/crane) resolves the digest of the published
   image, [syft](https://github.com/anchore/syft) generates its SBOMs (CycloneDX and SPDX JSON), and a signed build
   provenance and SBOM attestation are created for the digest, see [Supply chain](../deployment/supply-chain.md).
5. The tag `v<version>` and a [GitHub release](https://github.com/Ch4s3r/mergeable-rs/releases) with the changelog
   generated by git-cliff (features, bug fixes, performance, refactoring, documentation, build, CI and tests; `chore`
   commits are left out), the image name and digest, and the two SBOMs as assets are created.

Because pull requests are squash-merged, the pull request title is the commit that decides the version bump.

## Image tags

| Tag | Meaning |
|---|---|
| `<version>` (e.g. `0.4.2`) | one release, never moves; use it in production |
| `latest` | the most recent release |

## Dependency updates

[Renovate](https://docs.renovatebot.com) (`renovate.json`, built from presets) keeps the dependencies up to date: Cargo
crates, GitHub Actions, the Paketo builder and buildpacks in `project.toml`, the Dockerfile images, devenv (the devenv
version and the pinned `devenv-nixpkgs` commit) and the npm dependencies of this documentation site
(`website/package.json`). Updates are opened on Mondays before 04:00 UTC; patch, minor, digest and lock file updates
are squash-merged automatically once all checks pass, major updates wait for review. Renovate also opens pull requests
for direct dependencies with known vulnerabilities in the [OSV database](https://osv.dev) as soon as a fix is available,
regardless of the schedule.

### Security fixes

[Dependabot alerts](https://docs.github.com/en/code-security/dependabot/dependabot-alerts/about-dependabot-alerts) are
enabled for the repository, Dependabot security updates are not, so there is a single source of fix pull requests:
Renovate reads the Dependabot alerts (the [Mend Renovate app](https://github.com/apps/renovate) has `read` access to
Dependabot alerts by default) and the OSV alerts and opens the fix pull requests immediately. They carry the
`security` label and are squash-merged automatically once all checks pass, also when the fix is a major update
(`vulnerabilityAlerts` in `renovate.json`).

To enable the alerts on a fork:

```sh
gh api -X PUT repos/<owner>/<repo>/vulnerability-alerts
gh api -i repos/<owner>/<repo>/vulnerability-alerts   # 204: enabled, 404: disabled
```
